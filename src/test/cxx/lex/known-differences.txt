# Runs of bench/cxx-lex.py whose difference from clang is understood:
# either the front end follows the standard where clang does not, or clang's
# result comes from a phase the C++ front end does not have yet.  The harness
# reports such a run as "known" instead of FAIL when only the listed
# comparisons differ.  Check a new entry's diff with
# `bench/cxx-lex.py TEST` after emptying this file.
#
# test (path under src/test/cxx/lex) | comparisons | why
#
# [lex.ppnumber], [diff.cpp14.lex]/2: from C++17 "pp-number 'p' sign" holds
# in any pp-number, so 0p+3 and 0x42_amp+3 are one token each.  clang keeps
# its C++14 extension rule (p sign only after 0x, without '_') in every mode.
llvm/Lexer/hexfloat.cpp [-std=c++17] | raw tokens diags | 0p+3 is one pp-number in C++17
# [lex.ppnumber]: pp-number ''' nondigit, then pp-number 'e' sign: 0x1'e+1
# is one pp-number.  clang forgets the 'e' after a digit separator.
llvm/Lexer/cxx1y_digit_separators.cpp | raw tokens diags | 0x1'e+1 is one pp-number

# Later phases.
# [lex.ext]/3: the literal operator found decides whether 9000..._x1 must fit
# unsigned long long; clang's error comes from that lookup.
llvm/CXX/lex/lex.literal/lex.ext/p3.cpp | diags | needs [lex.ext]/3, [over.literal]
# [cpp.import], [cpp.module]: clang -E writes the import and module
# directives as __preprocessed_import/__preprocessed_module, which its phase 4
# turns back into import/module keywords.
llvm/CXX/lex/lex.pptoken/p3-2a.cpp | tokens | needs phase 4 ([cpp.import])
llvm/Lexer/cxx20-module-directive.cpp | tokens | needs phase 4 ([cpp.module])
# [lex.ext]/4: 1e5000_x is passed as the long double 1e5000L only if lookup
# finds a literal operator taking long double; clang's range warning comes
# from that call.
llvm/CXX/lex/lex.literal/lex.ext/p4.cpp | diags | needs [lex.ext]/4, [over.literal]
# clang -dump-tokens counts as "preprocessed output", where clang leaves
# U+00A0 a token instead of white space; when it compiles (-fsyntax-only) it
# takes it as white space, as the front end does, and the diagnostics agree.
spec/lex.name.cpp | tokens | clang's -dump-tokens mode skips its Unicode white space extension
