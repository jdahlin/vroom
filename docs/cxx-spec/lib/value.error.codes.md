# 16.5.5.15 Value of error codes [value.error.codes]

[Contents](../README.md) · up: [16.5.5 Conforming implementations \[conforming\]](conforming.md) · prev: [16.5.5.14 Restrictions on storage of pointers \[res.on.pointer.storage\]](res.on.pointer.storage.md) · next: [16.5.5.16 Moved-from state of library types \[lib.types.movedfrom\]](lib.types.movedfrom.md)

**1** Certain functions in the C++ standard library report errors via a `std::error_code` ([[syserr.errcode.overview]](syserr.errcode.overview.md)) object. That object’s `category()` member shall return `std::system_category()` for errors originating from the operating system, or a reference to an implementation-defined `error_category` object for errors originating elsewhere. The implementation shall define the possible values of `value()` for each of these error categories. [*Example 1*: For operating systems that are based on POSIX, implementations should define the `std::system_category()` values as identical to the POSIX `errno` values, with additional values as defined by the operating system’s documentation. Implementations for operating systems that are not based on POSIX should define values identical to the operating system’s values. For errors that do not originate from the operating system, the implementation may provide enums for the associated values. — *end example*]
