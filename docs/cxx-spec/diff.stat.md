# C.5.4 [[stmt.stmt]](stmt.stmt.md): statements [diff.stat]

[Contents](README.md) · up: [C.5 C++ and ISO C \[diff.iso\]](diff.iso.md) · prev: [C.5.3 [[expr]](expr.md): expressions \[diff.expr\]](diff.expr.md) · next: [C.5.5 [[dcl.dcl]](dcl.dcl.md): declarations \[diff.dcl\]](diff.dcl.md)

**1** **Affected subclauses:** [[stmt.switch]](stmt.switch.md), [[stmt.goto]](stmt.goto.md) <br>**Change:** It is now invalid to jump past a declaration with explicit or implicit initializer (except across entire block not entered). <br>**Rationale:** Constructors used in initializers may allocate resources which need to be de-allocated upon leaving the block. Allowing jump past initializers would require complicated runtime determination of allocation. Furthermore, any use of the uninitialized object could be a disaster. With this simple compile-time rule, C++ assures that if an initialized variable is in scope, then it has assuredly been initialized. <br>**Effect on original feature:** Deletion of semantically well-defined feature. <br>**Difficulty of converting:** Semantic transformation. <br>**How widely used:** Seldom.

**2** **Affected subclause:** [[stmt.return]](stmt.return.md) <br>**Change:** It is now invalid to return (explicitly or implicitly) from a function which is declared to return a value without actually returning a value. <br>**Rationale:** The caller and callee may assume fairly elaborate return-value mechanisms for the return of class objects. If some flow paths execute a return without specifying any value, the implementation must embody many more complications. Besides, promising to return a value of a given type, and then not returning such a value, has always been recognized to be a questionable practice, tolerated only because very-old C had no distinction between void functions and int functions. <br>**Effect on original feature:** Deletion of semantically well-defined feature. <br>**Difficulty of converting:** Semantic transformation. Add an appropriate return value to the source code, such as zero. <br>**How widely used:** Seldom. For several years, many existing C implementations have produced warnings in this case.
