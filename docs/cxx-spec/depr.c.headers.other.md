# D.9.6 Other C headers [depr.c.headers.other]

[Contents](README.md) · up: [D.9 C headers \[depr.c.headers\]](depr.c.headers.md) · prev: [D.9.5 Header `<tgmath.h>` synopsis \[depr.tgmath.h.syn\]](depr.tgmath.h.syn.md) · next: [D.10 Requires paragraph \[depr.res.on.required\]](depr.res.on.required.md)

**1** Every C header other than `<complex.h>` ([[depr.complex.h.syn]](depr.complex.h.syn.md)), `<iso646.h>` ([[depr.iso646.h.syn]](depr.iso646.h.syn.md)), `<stdalign.h>` ([[depr.stdalign.h.syn]](depr.stdalign.h.syn.md)), `<stdbool.h>` ([[depr.stdbool.h.syn]](depr.stdbool.h.syn.md)), and `<tgmath.h>` ([[depr.tgmath.h.syn]](depr.tgmath.h.syn.md)), each of which has a name of the form `<name.h>`, behaves as if each name placed in the standard library namespace by the corresponding `<cname>` header is placed within the global namespace scope, except for the functions described in [[sf.cmath]](lib/sf.cmath.md), the declaration of `std::byte` ([[cstddef.syn]](lib/cstddef.syn.md)), and the functions and function templates described in [[support.types.byteops]](lib/support.types.byteops.md). It is unspecified whether these names are first declared or defined within namespace scope ([[basic.scope.namespace]](basic.scope.namespace.md)) of the namespace `std` and are then injected into the global namespace scope by explicit *using-declaration*s ([[namespace.udecl]](namespace.udecl.md)).

**2** [*Example 1*: The header `<cstdlib>` assuredly provides its declarations and definitions within the namespace `std`. It may also provide these names within the global namespace. The header `<stdlib.h>` assuredly provides the same declarations and definitions within the global namespace, much as in the C Standard. It may also provide these names within the namespace `std`. — *end example*]
