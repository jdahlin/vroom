# Builtin demand

Generated by `bench/vcc-builtins-demand.py` (`--out`); **regenerated by hand**: its inputs are the project trees under `work/` (git-ignored) and LLVM 23 in `/usr/lib/llvm-23`, which a checkout does not have, so no `--check` verifies that this file is current.  No compiler code is involved: the classes below are what `vpp` says today.  See doc/PLAN-builtins.md, "Demand".

## Method

- Scan: every `__builtin_*`, `__atomic_*`, `__sync_*`, `__c11_atomic_*` identifier and every x86 (`_mm*`), NEON and ACLE intrinsic in the projects' `.S .c .cc .cpp .cxx .def .h .hh .hpp .hxx .inc .inl .ipp` files, outside comments and string literals (a regular-expression tokenizer, not vcc's lexer), not as the operand of `__has_builtin` and friends.  Code under `#if 0` or for another target is counted (the scan has no preprocessor); the directories `Documentation`, `doc`, `docs` and `.git` are skipped.
- An intrinsic counts for the builtins clang's own header (`/usr/lib/llvm-23/lib/clang/23/include`) calls for it, transitively through other intrinsics: a reference to `_mm_add_epi8` is a reference to what `emmintrin.h` needs.  "refs" is direct references plus those.  An intrinsic that needs no builtin (plain vector operators) does not appear.
- Classes, per name, best over aarch64-linux-gnu and x86_64-linux-gnu: `consistent` (in vcc's table, no line in `src/test/builtins/consistency-failures.txt`), `known` (in the table, with lines there: the invariants are listed), `unchecked` (implemented, outside the consistency check: special forms, the unsuffixed `__sync_*` forms, ...), `stub` (clang knows it, vcc answers "is not implemented"), `unknown` (clang knows it, vcc answers "undeclared function"), `not-builtin` (not a clang builtin: a project's own `__atomic_foo`, left out of the tables).
- `known` is not one level: `constexpr-claimed-not-folded` lines are benign (clang does not fold those calls either); `not-compiled`, `c-only-callable`, `claimed-not-callable` and `crash` are the ones that block a build.  A name valid on one target only (`__builtin_ia32_*` on arm64) is judged by the table, which has no target; a name the table lacks, by the better of the two probes.
