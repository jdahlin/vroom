# Style: files, names, comments

The rules a module follows once it has had its quality pass
(`PLAN-quality.md`).  The aim is that someone new can find the code for a
job from its name, and understand a file from its first lines.  Formatting
(tabs, kernel brace style) is unchanged and not covered here.

Paths are those of the reorganised tree (`src/`, PR #134).

## Files

1. **One job per file.**  A pass, a table, a data structure, a file format's
   reader.  If describing the file needs "and", it is two files.  An
   exception is allowed where splitting would hurt (a hot loop with its
   helpers, a table and its only reader); the file's opening comment says
   why.
2. **The name says the job** in full words, with hyphens between words:
   `macro-expand.c`, `header-cache-replay.c`, `copy-propagation.c`,
   `archive-reader.c`.  No name that only says where the code came from or
   who uses it (`setup.c`, `util.c`, `misc.c`, `tu.c`, `impl`).
3. **One meaning per word across the tree.**  The glossary at the end owns
   the words that have been used for several things (`replay`, `flow`,
   `arena`, `buf`, `put`, `reserve`, `hash`).
4. **Size is a signal, not a rule**: a file over about 1500 lines or a
   function over about 300 lines is expected to say in a comment why it is
   one thing.
5. **Headers.**  `NAME.h` in `src/include/MODULE/` is what other modules may
   use.  A module's shared internals are in one header beside its files,
   named `MODULE-internal.h` (today's `*impl.h`).  A header that only one
   `.c` file includes is folded into it.
6. Generated files open with `/* generated by TOOL from SOURCE: do not edit */`.

## Names

### Functions

`module_noun_verb`, in full words:

```
pp_macro_expand        ld_archive_member_add      a64_record_copy_propagate
cc_type_intern         vir_block_dominators_build as_expression_parse
```

1. **Every file-scope function has its module's prefix**, static or not.
   Modules are compiled as one translation unit, so a static name is visible
   to the whole module, and a bare `mem`, `slot`, `put` or `expr` says
   nothing in a call.
2. **Noun before verb**, so everything about one thing sorts together:
   `ld_symbol_find`, `ld_symbol_define`, `ld_symbol_resolve`.  The noun is
   the thing acted on; leave it out only when it is the module itself
   (`pp_open`).
3. **Full words.**  Allowed abbreviations are this list and nothing else:
   the module prefixes below; `ast`, `cfg`, `abi`, `tls`, `got`, `plt`,
   `elf`, `fp`, `simd`, `id`, `ptr`, `len`, `cap`, `max`, `min`, `tmp`,
   `init`, `alloc`, `eval`, `cmp`, `src`, `dst`, `reg`, `imm`, `insn`,
   `reloc`, `sym` only as a struct tag that already exists.  Standard names
   of the domain stay as the standard writes them (`leb128`, `xxh3`,
   `adrp`, AAPCS64 terms).
4. A predicate reads as one: `cc_expression_has_side_effects`,
   `vir_block_is_reachable`.  A function that can fail the job says so in
   its comment, not its name.

### Module prefixes

| Module | Prefix | Module | Prefix |
|---|---|---|---|
| `common/`, `port/` | `v` + facility: `vvec_`, `vbuffer_`, `vregion_`, `vfile_` | `vir/` | `vir_` |
| `frontend/lex/` | `lex_` | VIR builder (`codegen/vir/`) | `virbuild_` |
| `frontend/pp/` | `pp_` | `as/` | `as_` |
| `diag/` | `diag_` | `obj/` | `obj_` |
| AST and types (language-neutral) | `ast_` | `ld/` | `ld_` |
| `frontend/c/` (parser, sema) | `cc_` | `driver/` | `driver_` |
| `codegen/` shared | `codegen_` | `server/` | `vccd_` |
| `codegen/walk/` | `walk_` | `utils/` | the tool: `ar_`, `shell_`, `fixdep_` |
| `codegen/rec/` | `record_` | `arch/a64/` | `a64_` |
| `platform/OS/` | the format: `elf_`, `macho_` | `arch/x64/` | `x64_` |

A target's code in a shared module carries both: `a64_as_`, `x64_ld_`.

### Types, constants, macros

- Types: `module_noun` in lower case, no `_t`: `ld_symbol`, `pp_macro`,
  `vir_block`.  The context a module passes everywhere is `MODULE_context`
  and its variable is `ctx` (not `c`, `e`, `E`, `W`, `L`).
- Enumerators and constants: `MODULE_NOUN_VALUE`: `VIR_OP_ADD`,
  `LD_SECTION_ALLOC`.
- Macros that are not constants: `MODULE_VERB` or `V...` for the library;
  function-like macros that evaluate an argument twice say so.

### State

- **Struct fields and globals are words**: `inline_marks_changed`, not
  `mf`; `live_after`, not `la`; `stack_offset`, not `soff`.  A field's
  comment gives its unit and who writes it when that is not obvious.
- **Locals** may be short where the scope is short and the convention is
  old: `i`, `n`, `p`, `s`, `x` for the current node.  A local that lives
  across more than a screen gets a word.
- No two things in one module share a one-letter name (`W` is today three
  structs).

## Comments

- **Every file opens with a comment**: what the file does in one sentence;
  then what a reader must know before changing it (inputs and outputs,
  invariants, who calls it, thread rules, what fails the job).  Not the
  history, not the list of functions.
- **Every module has one overview**, the opening comment of its public
  header: what the module is for, its data structures and their lifetimes,
  the order things happen in, and its dependencies.  `ARCHITECTURE.md`
  links to these and does not repeat them.
- A comment says why, or what must hold; code that needs a comment to say
  what it does gets a better name instead.
- A comment that names another file, function or number is checked when
  that thing moves (`bench/quality.py` will check file names).

## Errors

From `PLAN-quality.md`'s decisions: bad input, a limit or out-of-memory
ends the job with a diagnostic (`vjob_fail`) and never the server; `VBUG()`
is the one way to stop on an internal inconsistency; a standalone tool
prints and exits through the same two.  No `abort()`, `exit()` or
`fprintf(stderr, ...)` elsewhere.

## Glossary of reserved words

| Word | Means only | Was also |
|---|---|---|
| region | a bump allocator over reserved address space (`vregion`) | arena (five things) |
| buffer | growable bytes (`vbuffer`); `text_buffer` for the emitter's fixed one | buf (ten types) |
| append | add bytes at the end of a buffer | put, add, push, s |
| store / load | write / read a value at a pointer, by width and byte order | put, wr, rd, p32 |
| emit | add a machine record or instruction to the function | put, ins, gen |
| reserve | map address space | ensure capacity (that is `need`) |
| table hash / digest | `vhash_*` for tables; `vdigest_*` for XXH3, BLAKE3, SHA-256 | hash, ldhash |
| serve | header cache: hand recorded tokens to the preprocessor | replay |
| replay | declaration cache: apply recorded front-end state in another TU | |
| commit | emitter: feed a function's chunks to the assembler and object | replay |
| flow | data flow over machine records | reachability walks in the front end (those are `reach`) |

A module's pass adds its own terms here.
